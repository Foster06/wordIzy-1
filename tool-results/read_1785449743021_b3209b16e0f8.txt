     1→# wordIzy
     2→
     3→> Free word unscrambler & anagram solver with 9-language official Scrabble dictionaries. 12 tools, no sign-up, no tracking. Built with Next.js 16, Prisma, and Tailwind CSS.
     4→
     5→A privacy-first word puzzle platform built for word game enthusiasts, students, and language lovers worldwide. Whether you're stuck on a Wordle puzzle, looking for the best Scrabble play, or exploring a new language, wordIzy gives you the answers without friction, sign-ups, or paywalls.

    48→## Features
    49→
    50→### 12 Word Tools
    51→
    52→| Tool | Description |
    53→|------|-------------|
    54→| **Word Unscrambler** | Enter scrambled letters (e.g., `SRAABLC`), find every valid dictionary word. Supports wildcards (`?` and `*`), advanced filters (starts with, ends with, must include), and groups results by length with Scrabble scores. |
    55→| **Scramble Solver** | Solve scrambled word puzzles. Enter any jumble of letters and get all valid words that can be formed. |
    56→| **Anagram Solver** | Find all anagrams from any set of letters. Perfect for anagram puzzles and word games. |
    57→| **Wordle Solver** | Enter your green/yellow/grey clues (placed letters, valid letters, excluded letters) and get every possible Wordle answer. Supports 5–7 letter words. |
    58→| **Quordle Solver** | Solve 4 Wordles simultaneously. Add multiple boards with independent clue sets and find words that match all boards. |
    59→| **Scrabble Duplicate** | Duplicate Scrabble gives every player the same rack. Enter your 7 letters (plus any board letters already placed) and find the highest-scoring plays, ranked by score. |
    60→| **Dictionary Checker** | Verify whether a word exists in the official Scrabble dictionary, see its Scrabble point value, and read a definition (pulled from Free Dictionary API and Wiktionary). |
    61→| **Random Word Generator** | Generate random valid words by length (2–7 letters) and count. Great for games, naming, and vocabulary practice. |
    62→| **Wordfeud Helper** | Find the best Wordfeud words from your tiles. Supports wildcards and all 9 language dictionaries. |
    63→| **Word Lists** | Browse every 2–7 letter word. Filter by length and starting/ending letter. Alphabetical, paginated, with live word counts on each length button. |
    64→| **Word Starts By** | Browse all words that start with a specific letter, filtered by length (2–7). Per-length word counts shown on number buttons. |
    65→| **Word Ends By** | Browse all words that end with a specific letter, filtered by length (2–7). Per-length word counts shown on number buttons. |

   107→### Smart Features
   108→
   109→- **Copy to clipboard** — One-click "Copy all" button on every result card copies the full word list (uppercase, newline-separated) to your clipboard with a "Copied!" confirmation
   110→- **Recent searches** — Your last 10 searches are saved locally (in `localStorage`) and appear as clickable chips below the search input for quick re-running
   111→- **Loading skeletons** — Shimmer-animated skeleton placeholders match the result grid layout for a smooth perceived loading experience (instead of a plain spinner)
   112→- **Progressive Web App** — Installable on phone or desktop via `manifest.json`. Full-screen, app-like experience with the wordIzy icon on your home screen
   113→- **Word counts on buttons** — The number buttons (2–7) on Word Lists, Word Starts By, and Word Ends By pages show live word counts per length, fetched from `/api/length-counts`
   114→- **Dictionary pre-warming** — On app load, a fire-and-forget request to `/api/warmup` pre-loads all 9 dictionaries into server memory so the first real search is fast
   115→- **Error boundaries** — Every tool is wrapped in a React error boundary so a crash in one tool doesn't break the whole page
   116→
   117→### Privacy & Security
   118→
   119→- **No accounts** — Nothing to sign up for, no login, no profile
   120→- **No cross-site tracking** — No fingerprinting, no tracking pixels, no cross-site cookies
   121→- **Anonymous search analytics** — Only the query string, tool used, language, and result count are recorded. No IP address, no user ID, no browser fingerprint
   122→- **Cookie consent banner** — Appears on first visit with Accept/Decline buttons. Choice stored in `localStorage`
   123→- **Contact form rate limiting** — Maximum 5 submissions per hour per IP address (in-memory, per-instance)
   124→- **Contact form data** — Name, email, and message stored in the database. Only accessible to the site owner via the password-gated inbox. Never shared with third parties
   125→- **GDPR & CCPA compliant** — Right to access, rectify, and erase personal data. No data sold or shared
   126→
   127→### Performance
   128→
   129→- **In-memory dictionary caching** — Dictionaries are loaded once and cached in a `Map` on the server. Subsequent searches are instant
   130→- **Per-length indexing** — Words are indexed by length (`byLength: Map<number, WordEntry[]>`) for O(1) length-based lookups
   131→- **Dictionary pre-warming** — All 9 dictionaries pre-loaded on server startup via `/api/warmup`
   132→- **Skeleton loading states** — Animated placeholders instead of spinners for better perceived performance
   133→- **Lazy loading** — Dictionaries load lazily on first use, then cached for all subsequent requests
   134→
   135→### Accessibility
   136→
   137→- **Semantic HTML** — Uses `<main>`, `<header>`, `<nav>`, `<footer>`, `<section>`, `<article>`
   138→- **ARIA labels** — All icon buttons have descriptive `aria-label`s
   139→- **`aria-current="page"`** — Active navigation items are marked for screen readers
   140→- **Keyboard navigation** — All interactive elements are keyboard accessible
   141→- **Focus visible** — Focus rings on all focusable elements
   142→- **Screen reader friendly** — `sr-only` class for screen reader-only content
   143→
   144→### SEO
   145→
   146→- **Per-route metadata** — Each of the 18 routes has a unique `<title>` and `<meta description>` that update on navigation
   147→- **JSON-LD structured data** — `WebApplication` schema in `<head>` with feature list, supported languages, and pricing
   148→- **Open Graph + Twitter cards** — `og:image` (1200×630 SVG), `og:title`, `og:description`, Twitter `summary_large_image` card
   149→- **`robots.txt`** — Allows all crawlers, blocks `/api/` and private pages
   150→- **`sitemap.xml`** — Lists the home page and all site pages with priority and changefreq
   151→- **`manifest.json`** — PWA manifest with app name, theme color, icons, and display mode

   176→## Quick Start
   177→
   178→### Prerequisites
   179→
   180→- [Node.js](https://nodejs.org/) 18+ or [Bun](https://bun.sh/)
   181→- A [Turso](https://turso.tech) account (free tier) — for production database
   182→- A [Vercel](https://vercel.com) account — for deployment
   183→- A [GitHub](https://github.com) account — for code hosting
   184→
   185→### Installation
   186→
   187→```bash
   188→# Clone the repo
   189→git clone https://github.com/YOUR-USERNAME/wordizy.git
   190→cd wordizy
   191→
   192→# Install dependencies
   193→bun install
   194→
   195→# Create .env file (see Environment Configuration below)
   196→touch .env
   197→# Then edit .env with your values
   198→
   199→# Generate Prisma client
   200→bunx prisma generate
   201→
   202→# Push database schema (creates tables in local SQLite)
   203→bun run db:push
   204→
   205→# Start the development server
   206→bun run dev
   207→```
   208→
   209→Open http://localhost:3000 in your browser.

   242→## Database
   243→
   244→### Local SQLite (Development)
   245→
   246→For local development, wordIzy uses a SQLite file at `db/custom.db`. This requires no setup beyond running `bun run db:push` after creating your `.env` file.
   247→
   248→### Turso (Production)
   249→
   250→Vercel's filesystem is ephemeral — local SQLite files get wiped on every deploy. For production, use [Turso](https://turso.tech) (hosted SQLite). The `db.ts` file automatically detects Turso when `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` are set, and falls back to local SQLite when they're not.
   251→
   252→### Database Schema
   253→
   254→The database has 4 tables (2 active, 2 legacy from template):
   255→
   256→| Table | Purpose | Active? |
   257→|-------|---------|---------|
   258→| `ContactMessage` | Contact form submissions (name, email, message, locale, handled, IP, userAgent) | ✅ Yes |
   259→| `SearchEvent` | Anonymous search analytics (query, route, lang, resultCount) | ✅ Yes |
   260→| `User` | Legacy template table | ❌ No |
   261→| `Post` | Legacy template table | ❌ No |
   262→
   263→**Indexes**: `ContactMessage` is indexed on `handled` and `createdAt`. `SearchEvent` is indexed on `route`, `lang`, `createdAt`, and `query`.

   267→## Deployment (Vercel)
   268→
   269→### Step 1: Create Turso Database
   270→
   271→```bash
   272→# Install Turso CLI (if you don't have it)
   273→curl -sSfL https://get.tur.so/install.sh | bash
   274→
   275→# Log in (opens browser)
   276→turso auth login
   277→
   278→# Create database
   279→turso db create wordizy
   280→
   281→# Get the connection URL (copy this)
   282→turso db show wordizy --url
   283→# → libsql://wordizy-xxx.turso.io
   284→
   285→# Get the auth token (copy this)
   286→turso db tokens create wordizy
   287→# → eyJhbGciOiJFZERTQSIsInR5cCI6IkpXVCJ9...
   288→
   289→# Create all tables in Turso
   290→turso db shell wordizy < schema.sql
   291→```
   292→
   293→Alternatively, you can push the schema using Prisma:
   294→```bash
   295→# Set Turso env vars in .env first, then:
   296→TURSO_DATABASE_URL="libsql://wordizy-xxx.turso.io" \
   297→TURSO_AUTH_TOKEN="your-token" \
   298→bun run db:push
   299→```
   300→
   301→### Step 2: Push to GitHub
   302→
   303→```bash
   304→git init
   305→git add .
   306→git commit -m "wordIzy — ready for deployment"
   307→git branch -M main
   308→git remote add origin https://github.com/YOUR-USERNAME/wordizy.git
   309→git push -u origin main
   310→```
   311→
   312→The `.env` file will NOT be pushed (it's in `.gitignore`).

   314→### Step 3: Deploy on Vercel
   315→
   316→1. Go to [vercel.com/new](https://vercel.com/new)
   317→2. Click **"Import Git Repository"**
   318→3. Select your `wordizy` repo
   319→4. In the **Environment Variables** section, add:
   320→
   321→| Name | Value | Required? |
   322→|------|-------|-----------|
   323→| `DATABASE_URL` | `file:./db/custom.db` | ✅ Yes |
   324→| `ADMIN_PASSWORD` | Your strong password | ✅ Yes |
   325→| `TURSO_DATABASE_URL` | `libsql://wordizy-xxx.turso.io` | ✅ Yes (for Vercel) |
   326→| `TURSO_AUTH_TOKEN` | Your Turso auth token | ✅ Yes (for Vercel) |
   327→| `NEXT_PUBLIC_ADSENSE_CLIENT` | `ca-pub-XXXXXXXXXXXXXXXX` | ❌ Optional |
   328→| `RESEND_API_KEY` | `re_xxxxxxxxxxxx` | ❌ Optional |
   329→| `NOTIFY_EMAIL` | `dorciusforteson@gmail.com` | ❌ Optional |
   330→
   331→5. Click **Deploy**
   332→6. Wait 2–3 minutes for the build to complete

   515→## Internationalization
   516→
   517→All UI text is driven by `src/components/i18n/translations.ts` (1,845 lines). The `LanguageProvider` context loads the saved language from `localStorage` on mount and falls back to English.
   518→
   519→To add a new language:
   520→1. Add the language code to `LanguageCode` in `src/lib/languages.ts`
   521→2. Add the language definition (flag, native name, letter values, tile counts) to the `LANGUAGES` object
   522→3. Add the full translation block to `translations.ts`
   523→4. Add the language to the `LANGUAGE_LIST` export

   558→## Known Limitations
   559→
   560→- **Hash-based routing** — Search engines see only one URL. Per-route meta tags update client-side via JavaScript. If SEO is critical, consider migrating to App Router pages with real URLs.
   561→- **German & Portuguese dictionaries** — Use curated filtered lists, not official Scrabble lists (which are proprietary). Some words may differ from tournament play.
   562→- **Inbox & Dashboard auth** — Shared password gate, not real authentication. Don't use for sensitive data without upgrading to NextAuth.js.
   563→- **Rate limiting** — In-memory, per-instance. In a multi-instance deployment, each instance has its own counter. Use Upstash Redis for global rate limiting.
   564→- **Analytics storage** — Stored in the same SQLite/Turso database. For high-traffic sites, consider a dedicated analytics service.
